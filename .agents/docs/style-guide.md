# BridgeWork Frontend Style Guide

## 1. 문서 목적

이 문서는 BridgeWork 프론트엔드의 UI 스타일, 레이아웃, 색상, 타이포그래피, 컴포넌트 표현 방식을 정의한다.

BridgeWork는 장애인 구직자를 위한 접근성 기반 일자리 추천 서비스이므로, 단순히 보기 좋은 UI보다 다음 기준을 우선한다.

- 글자가 충분히 커야 한다.
- 클릭 영역이 넓어야 한다.
- 정보 구조가 명확해야 한다.
- 지도 정보는 목록과 함께 제공되어야 한다.
- 색상만으로 상태를 표현하지 않아야 한다.
- 접근성 점수, 위험 요인, 확인 필요 항목이 직관적으로 보여야 한다.
- 전체 UI는 깔끔하고 신뢰감 있는 공공 서비스 느낌을 유지한다.

---

## 2. 디자인 방향

BridgeWork의 UI는 다음 인상을 목표로 한다.

- 신뢰감 있는 공공 서비스
- 장애인 구직자를 배려한 큰 글씨와 넓은 터치 영역
- 지도 기반 서비스에 적합한 정보 밀도
- 공고, 접근성, 기업 정보를 한 화면에서 비교할 수 있는 구조
- 복잡한 데이터를 카드와 탭으로 정리한 화면
- 파란색 중심의 안정적인 인터페이스
- 접근성 점수는 초록, 노랑, 빨강 계열로 명확히 구분

기능 3 지역 접근성 지도 화면의 핵심 구조는 다음과 같다.

- 상단 검색 바
- 좌측 사이드 네비게이션
- 좌측 교통 필터 패널
- 중앙 지도 영역
- 우측 공고 상세 패널
- 우측 하단 고정 액션 버튼 영역

## 3. 폰트

### 3.1 기본 폰트

BridgeWork의 기본 폰트는 Pretendard를 사용한다.

권장 font-family는 다음과 같다.

- Pretendard
- -apple-system
- BlinkMacSystemFont
- system-ui
- sans-serif

### 3.2 폰트 사용 원칙

- 전체 UI는 기본적으로 크게 설계한다.
- 본문 텍스트는 최소 15px 이상을 권장한다.
- 버튼, 탭, 필터, 카드 텍스트는 14px 미만으로 내려가지 않는다.
- 중요한 정보는 굵기와 크기를 함께 사용한다.
- 회색 작은 글씨만으로 중요한 정보를 표시하지 않는다.
- 숫자 점수, 마감일, 등급은 시각적으로 강하게 표현한다.

### 3.3 타입 스케일

| 용도 | 크기 | 굵기 | 사용 예시 |
|---|---:|---:|---|
| Page Title | 24px | 700 | 페이지 제목 |
| Panel Title | 20px | 700 | 교통 필터, 접근성 점수 |
| Card Title | 18px | 700 | 상담원, 회사명 |
| Section Title | 17px | 700 | 상세정보, 사업장 주소 |
| Body Large | 16px | 500 | 주요 본문 |
| Body | 15px | 400/500 | 일반 설명 |
| Caption | 13px | 400/500 | 보조 정보 |
| Badge Text | 13px | 600 | 공공, 표준사업장 |
| Button | 15px | 700 | 지원하기, 경로 안내 |
| Score Number | 36px ~ 44px | 700 | 접근성 점수 |
| D-Day | 22px ~ 28px | 700 | D-3 |

### 3.4 숫자 표현

접근성 점수, D-Day, 통근 시간, 거리 등 숫자는 일반 본문보다 강하게 표현한다.

예시:

- 접근성 95점
- D-3
- 총 49분
- 도보 620m
- 환승 1회

숫자는 사용자가 빠르게 스캔할 수 있도록 굵게 표시한다.

## 4. 색상

### 4.1 Primary Color

BridgeWork는 파란색을 주요 색상으로 사용한다.

| 토큰명 | 색상 | 용도 |
|---|---|---|
| Primary | #2F7DF6 | 주요 버튼, 활성 탭, 선택 필터 |
| Primary Dark | #0B2F5B | 좌측 사이드바, 핵심 네비게이션 |
| Primary Light | #EAF2FF | 선택된 필터 배경, 정보 박스 |
| Primary Border | #BFD7FF | 선택된 chip, active border |

### 4.2 Neutral Color

| 토큰명 | 색상 | 용도 |
|---|---|---|
| Text Primary | #111827 | 제목, 주요 텍스트 |
| Text Secondary | #4B5563 | 보조 설명 |
| Text Tertiary | #6B7280 | 캡션, 부가 정보 |
| Text Disabled | #9CA3AF | 비활성 텍스트 |
| Border | #E5E7EB | 카드, 패널 구분선 |
| Border Strong | #D1D5DB | 입력창, 카드 외곽 |
| Background | #F8FAFC | 전체 배경 |
| Surface | #FFFFFF | 카드, 패널 |
| Surface Muted | #F3F6FA | 보조 카드 배경 |

### 4.3 Accessibility Status Color

접근성 상태는 색상만으로 표현하지 않고 반드시 텍스트와 함께 표시한다.

| 상태 | 색상 | 텍스트 | 의미 |
|---|---|---|---|
| GOOD | #1F9D55 | 접근 양호 | 현재 데이터 기준 접근성이 좋음 |
| CAUTION | #F5B82E | 주의 필요 | 일부 항목 확인 필요 |
| RISK | #E5484D | 확인 필요 항목 많음 | 접근성 판단이 제한적이거나 확인 항목이 많음 |
| UNKNOWN | #9CA3AF | 데이터 미확인 | 데이터가 부족하거나 아직 연동되지 않음 |

### 4.4 Job Badge Color

공고 카드와 상세 패널에는 다음 배지를 사용한다.

| 배지 | 스타일 |
|---|---|
| 공공 | 연한 파란 배경 + 파란 텍스트 |
| 표준사업장 | 연한 파란 배경 + 파란 텍스트 |
| A등급 | 연한 초록 배경 + 초록 텍스트 |
| B등급 | 연한 노랑 배경 + 노랑/갈색 텍스트 |
| C등급 | 연한 빨강 배경 + 빨강 텍스트 |
| D-Day | 빨강 텍스트 |
| 확인 필요 | 연한 회색 또는 노랑 배경 |

### 4.5 색상 사용 금지 규칙

다음 방식은 사용하지 않는다.

- 초록색 점만 표시하고 “접근 양호” 텍스트를 생략하는 방식
- 빨간색만으로 위험을 표현하는 방식
- 필수 입력 오류를 테두리 색상만으로 표시하는 방식
- 차트나 점수에서 범례 없이 색상만 사용하는 방식

항상 색상 + 텍스트 + 필요 시 아이콘을 함께 사용한다.

## 5. 레이아웃

### 5.1 전체 구조

기능 3 지도 화면은 다음 레이아웃을 기본으로 한다.

| 영역 | 권장 크기 | 설명 |
|---|---:|---|
| Top Header | 56px ~ 64px | 로고, 출발지 검색, 장애 유형 탭 |
| Left Nav | 56px ~ 72px | 아이콘 기반 주요 네비게이션 |
| Filter Panel | 300px ~ 340px | 교통 필터, 검색 결과 목록 |
| Map Area | Flexible | 지도, 경로, 접근성 마커 |
| Detail Panel | 360px ~ 420px | 공고 정보, 기업 정보, 접근성 정보 |
| Bottom Action Bar | 64px ~ 76px | 찜, 경로 안내, 지원하기 |

### 5.2 화면 비율

데스크톱 기준 추천 비율은 다음과 같다.

- 좌측 네비게이션: 약 4%
- 좌측 필터 패널: 약 18% ~ 22%
- 중앙 지도 영역: 약 50% ~ 56%
- 우측 상세 패널: 약 24% ~ 28%

지도 중심 서비스이므로 중앙 지도 영역은 가장 넓게 유지한다.

### 5.3 패널 구조

좌측 필터 패널과 우측 상세 패널은 흰색 배경을 사용한다.

패널 구분은 강한 그림자보다 얇은 border를 우선한다.

권장 스타일:

- background: white
- border-right 또는 border-left: 1px solid #E5E7EB
- panel 내부 padding: 16px ~ 20px
- 카드 간격: 10px ~ 12px

### 5.4 카드 구조

공고 카드, 상세 정보 카드, 접근성 점수 카드는 다음 기준을 따른다.

- border-radius: 8px 기본
- border: 1px solid #E5E7EB
- padding: 16px
- background: white
- hover 시 border-color 또는 background만 약하게 변경
- 과한 shadow는 사용하지 않음

### 5.5 여백 기준

| 용도 | 값 |
|---|---:|
| 페이지 외곽 여백 | 16px ~ 24px |
| 패널 내부 여백 | 16px ~ 20px |
| 카드 내부 여백 | 14px ~ 18px |
| 카드 간격 | 10px ~ 12px |
| 섹션 간격 | 20px ~ 28px |
| 버튼 내부 좌우 여백 | 16px ~ 24px |
| 버튼 내부 상하 여백 | 10px ~ 14px |

## 6. 상단 헤더

### 6.1 구성 요소

상단 헤더에는 다음 요소를 배치한다.

- BridgeWork 로고
- 출발지 검색 입력창
- 장애 유형 빠른 전환 탭
    - 지체
    - 시각
    - 청각

### 6.2 출발지 검색창

검색창은 크고 명확하게 제공한다.

권장 스타일:

- height: 40px ~ 48px
- border-radius: 10px ~ 12px
- placeholder: 출발지: [지하철역/주소 입력]
- 좌우 여백 충분히 확보
- focus 상태에서 primary border 표시

### 6.3 장애 유형 탭

장애 유형 탭은 우측 상단에 배치한다.

각 탭은 현재 화면의 접근성 기준을 바꾸는 핵심 컨트롤이므로 크고 명확해야 한다.

탭 예시:

- 지체 · 휠체어
- 시각 · 저시력, 전맹
- 청각 · 농난청

선택된 탭은 흰색 또는 연한 파란 배경과 파란 텍스트로 표시한다.

## 7. 좌측 사이드 네비게이션

### 7.1 목적

좌측 사이드 네비게이션은 주요 기능으로 빠르게 이동하기 위한 영역이다.

### 7.2 스타일

- 배경색: Primary Dark
- 아이콘 색상: white 또는 연한 회색
- 선택된 메뉴: 더 밝은 배경 블록
- 아이콘 버튼 크기: 최소 44px 이상
- border-radius: 8px ~ 12px

### 7.3 권장 메뉴

- 홈
- 지도
- 공고
- 체크리스트
- 마이페이지
- 설정

### 7.4 접근성

아이콘만 보이는 메뉴는 반드시 aria-label 또는 tooltip을 제공한다.

예시:

- 홈
- 지도 보기
- 공고 목록
- 지원 체크리스트
- 마이페이지
- 설정

## 8. 교통 필터 패널

### 8.1 목적

교통 필터 패널은 사용자가 통근 조건과 접근성 조건의 우선순위를 설정하는 영역이다.

### 8.2 구성

기능 3 화면 기준으로 다음 항목을 포함한다.

- 패널 제목: 교통 필터
- 안내 문구: 드래그하여 검색 우선순위를 설정해보세요.
- 통근시간
- 교통수단
- 환승 선호도
- 장애 유형별 맞춤 조건
- 검색 결과 개수
- 정렬 방식
- 공고 카드 목록

### 8.3 필터 우선순위 표시

각 필터는 번호를 붙여 우선순위를 보여준다.

예시:

- 1 통근시간
- 2 교통수단
- 3 환승 선호도
- 4 지체 맞춤

우선순위 번호는 primary blue로 표시한다.

드래그 핸들은 우측에 배치한다.

드래그 기능이 있더라도 키보드 또는 버튼으로 순서를 조정할 수 있는 대체 수단을 고려한다.

### 8.4 Chip 스타일

필터 선택지는 chip 형태로 제공한다.

기본 chip:

- background: white
- border: 1px solid #D1D5DB
- border-radius: 999px
- padding: 6px 10px
- font-size: 14px

선택된 chip:

- background: #EAF2FF
- border: 1px solid #2F7DF6
- color: #2F7DF6
- font-weight: 600

### 8.5 검색 결과 카드

공고 카드는 목록에서 빠르게 스캔할 수 있어야 한다.

표시 항목:

- 배지: 공공, A등급, 표준사업장
- D-Day
- 회사명
- 직무명
- 통근 시간
- 임금
- 고용형태

카드 내부는 너무 복잡하지 않게 유지한다.

카드 클릭 시 우측 상세 패널과 지도 선택 상태가 함께 변경된다.

### 8.6 선택된 공고 카드

선택된 공고 카드는 다음 방식으로 표시한다.

- border-color: Primary
- background: Primary Light 또는 white 유지
- 좌측에 얇은 primary indicator 사용 가능
- 카드 전체 클릭 영역 확보

## 9. 지도 영역

### 9.1 목적

지도 영역은 공고 위치, 통근 경로, 주변 접근성 정보를 시각화한다.

### 9.2 지도 위 요소

지도 위에는 다음 UI를 오버레이할 수 있다.

- 지도 레이어 버튼
- 지하철 엘리베이터/지상버스 노선 토글
- 접근성 점수 범례
- 선택된 경로
- 시간 범위 표시
- 마커 클러스터
- 현재 선택한 공고 위치

### 9.3 접근성 점수 범례

접근성 점수 범례는 지도 우측 상단에 배치한다.

예시:

- A: 80 이상
- B: 60 ~ 79
- C: 60 미만

색상 점과 텍스트를 함께 표시한다.

### 9.4 경로 색상

경로는 접근성 상태에 따라 구분한다.

- 접근 양호: 초록
- 주의 필요: 노랑
- 접근 어려움 또는 확인 필요 항목 많음: 빨강
- 일반 경로 또는 보조 경로: 회색 또는 연한 파랑

단, 경로 색상만으로 의미를 전달하지 않는다.

툴팁, 범례, 상세 패널에서 반드시 설명을 제공한다.

### 9.5 지도 대체 정보

지도 정보는 반드시 텍스트 목록으로도 제공한다.

대체 정보 예시:

- 총 소요 시간 49분
- 환승 1회
- 도보 620m
- 지하철 2호선 이용
- 엘리베이터 이용 가능
- 일부 환승 구간 확인 필요
- 매장 입구 경사 여부 확인 필요

## 10. 우측 상세 패널

### 10.1 목적

우측 상세 패널은 선택한 공고의 상세 정보, 기업 정보, 접근성 정보를 제공한다.

### 10.2 상단 정보

상단에는 다음을 표시한다.

- 배지: 공공, 표준사업장
- 마감일
- 공고명
- 회사명 또는 기관명
- D-Day
- 접근성 점수
- 탭 메뉴

### 10.3 탭 구성

공고 상세 패널은 다음 탭을 가진다.

- 접근성
- 공고정보
- 기업정보

선택된 탭은 primary blue 텍스트와 하단 border로 표시한다.

### 10.4 공고정보 탭

공고정보 탭에는 다음 항목을 표시한다.

- 모집직종
- 고용형태
- 임금
- 임금형태
- 요구경력
- 요구학력
- 모집기간
- 담당기관
- 연락처

각 항목은 label과 value를 좌우 또는 상하로 명확하게 구분한다.

label은 회색, value는 진한 텍스트를 사용한다.

### 10.5 기업정보 탭

기업정보 탭에는 다음 항목을 표시한다.

- 기관 또는 기업명
- 기업 유형
- 표준사업장 여부
- 사업장 주소
- 장애인 고용 현황
- 법정 의무 고용률
- 기업 설명

장애인 고용률은 숫자를 크게 표시한다.

예시:

- 4.8%
- 법정 의무 고용률 3.1%
- 법정 의무고용률을 초과 달성하고 있는 기업입니다.

### 10.6 접근성 탭

접근성 탭은 가장 중요한 탭이다.

표시 항목:

- 접근성 점수 원형 그래프
- 등급 배지
- 한 줄 요약
- 총 소요 시간
- 환승 횟수
- 도보 거리
- 상세 정보 목록
- 데이터 출처 안내
- 문제 없음, 주의, 확인 필요, 데이터 미확인 범례

### 10.7 접근성 점수 카드

접근성 점수 카드는 크게 보여준다.

권장 구성:

- 제목: 접근성 점수
- 도움말 아이콘
- 원형 점수 그래프
- 점수: 95 / 100
- 등급: A등급 · 지체 기준
- 요약: 출퇴근 가능
- 보조 설명: 큰 어려움 없이 출근할 수 있어요.
- 메타 정보: 총 49분, 환승 1회, 도보 620m

### 10.8 상세 접근성 정보

접근성 상세 정보는 리스트 형태로 제공한다.

각 항목은 다음 요소를 가진다.

- 상태 아이콘
- 항목명
- 설명
- 상태 배지

예시:

- 엘리베이터: 지하철 2개역, 역사 내 엘리베이터 이용 가능 / 접근 양호
- 환승 구간: 환승 거리 약 180m로 다소 길어요 / 주의 필요
- 경사 구간: 매장 입구 경사가 있어 휠체어 이용 시 주의가 필요해요 / 접근 어려움
- 저상버스 노선: 근처에 저상버스 노선이 있어 대체 이동이 가능해요 / 접근 양호
- 계단 없는 출입: 매장 출입구는 계단이 없어요 / 접근 양호

### 10.9 데이터 출처 안내

접근성 정보 하단에는 데이터 출처를 표시한다.

예시:

- 데이터 출처: 서울시 엘리베이터광장, 저상버스 노선 정보, 공공데이터포털
- 일부 정보는 최신 상태와 다를 수 있어 지원 전 확인을 권장합니다.

## 11. 하단 액션 영역

### 11.1 목적

우측 상세 패널 하단에는 사용자의 주요 액션을 고정한다.

### 11.2 구성

하단 액션 영역에는 다음 버튼을 둔다.

- 관심 공고
- 경로 안내
- 지원하기

### 11.3 버튼 우선순위

가장 중요한 CTA는 지원하기이다.

지원하기 버튼은 primary blue로 표현한다.

경로 안내 버튼은 secondary 버튼으로 표현한다.

관심 공고 버튼은 icon button으로 표현한다.

### 11.4 버튼 크기

- 높이: 최소 44px 이상
- 지원하기 버튼은 48px 이상 권장
- 모바일에서는 52px 이상 권장
- 아이콘 버튼도 최소 44px x 44px 확보

## 12. 버튼 스타일

### 12.1 Primary Button

용도:

- 지원하기
- 저장하기
- 다음 단계
- 추천 보기

스타일:

- background: Primary
- color: white
- border-radius: 10px ~ 12px
- height: 44px ~ 52px
- font-weight: 700

### 12.2 Secondary Button

용도:

- 경로 안내
- 이전 단계
- 다시 선택
- 필터 수정

스타일:

- background: white
- border: 1px solid Border Strong
- color: Text Primary
- border-radius: 10px ~ 12px
- height: 44px ~ 48px

### 12.3 Ghost Button

용도:

- 탭 보조 액션
- 상세 보기
- 옵션 열기

스타일:

- background: transparent
- color: Primary 또는 Text Secondary
- hover 시 연한 배경

### 12.4 Icon Button

용도:

- 찜
- 지도 이동
- 필터 순서 변경
- 설정
- 닫기

스타일:

- width: 최소 44px
- height: 최소 44px
- border-radius: 10px
- hover/focus 상태 제공
- aria-label 필수

## 13. 탭 스타일

### 13.1 상단 장애 유형 탭

선택된 탭:

- background: white
- color: Primary
- font-weight: 700
- shadow 또는 border로 선택 상태 표현

선택되지 않은 탭:

- background: Surface Muted
- color: Text Secondary

### 13.2 상세 패널 탭

공고 상세 패널의 탭은 underline 스타일을 사용한다.

- 선택된 탭: Primary color + 2px underline
- 기본 탭: Text Secondary
- hover: Text Primary

탭 텍스트는 최소 15px 이상으로 유지한다.

권장 스타일:

## 15. 접근성 등급 표시

### 15.1 등급 기준

접근성 등급은 다음 기준을 사용한다.

- A: 80점 이상
- B: 60 ~ 79점
- C: 60점 미만

### 15.2 사용자 표시 문구

내부 등급과 사용자 표시 문구를 분리한다.

| 내부 등급 | 사용자 표시 |
|---|---|
| A | 접근 양호 |
| B | 주의 필요 |
| C | 확인 필요 항목 많음 |

“접근 불가”, “위험”, “부적합”과 같은 단정적인 표현은 사용하지 않는다.

error 상태는 색상만으로 표시하지 않는다.

- 임금
- 고용형태

공고 카드 높이는 너무 낮게 잡지 않는다.

권장 최소 높이:

- 112px ~ 132px

### 17.2 정보 카드

정보 카드는 다음 용도로 사용한다.

- 사업장 주소

- 접근성 점수

정보 카드 스타일:

- border: 1px solid Border
- border-radius: 8px
- padding: 16px
- background: Surface

### 17.3 선택 카드

선택된 카드는 다음 중 하나 이상을 사용한다.

- primary border
- 연한 primary background
- 좌측 indicator
- 체크 아이콘

단, 선택 상태가 색상만으로 구분되지 않도록 텍스트 또는 아이콘을 함께 사용한다.

## 18. 아이콘 사용 원칙

### 18.1 아이콘 크기

| 용도 | 크기 |
|---|---:|
| 네비게이션 아이콘 | 22px ~ 24px |
| 버튼 내부 아이콘 | 18px ~ 20px |
| 상태 아이콘 | 20px ~ 24px |
| 보조 정보 아이콘 | 16px ~ 18px |

### 18.2 상태 아이콘

접근성 상세 정보에서는 상태별 아이콘을 함께 사용한다.

예시:

- 접근 양호: 체크 또는 초록 점
- 주의 필요: 주의 삼각형
- 확인 필요: 물음표 또는 정보 아이콘
- 데이터 미확인: 회색 점 또는 정보 아이콘

### 18.3 접근성

아이콘만으로 의미를 전달하지 않는다.

아이콘 버튼에는 aria-label을 제공한다.

## 19. 지도와 목록 동기화

### 19.1 기본 원칙

지도에서 선택한 공고와 좌측 공고 목록, 우측 상세 패널은 항상 동기화되어야 한다.

동작 원칙:

- 좌측 카드 클릭 시 지도 마커 선택
- 지도 마커 클릭 시 좌측 카드 선택
- 선택된 공고는 우측 상세 패널에 표시
- 우측 탭 변경은 선택된 공고를 유지
- 필터 변경 시 선택 상태 초기화 또는 첫 번째 결과 선택

### 19.2 선택 상태 표현

선택된 공고는 세 영역에서 일관되게 표현한다.

- 좌측 카드: 선택 border
- 지도 마커: 강조 마커
- 우측 패널: 공고 상세 표시

- 좌측 필터
- 중앙 지도
- 우측 상세

### 20.2 태블릿

태블릿에서는 우측 상세 패널을 drawer 또는 bottom sheet로 전환할 수 있다.

권장 구조:

- 좌측 필터 축소 가능
- 지도 중심

### 20.3 모바일

모바일에서는 3단 구조를 그대로 유지하지 않는다.

권장 구조:

- 상단 검색
- 지도
- 하단 공고 카드 sheet
- 필터는 별도 bottom sheet
- 상세 정보는 full screen page 또는 bottom sheet

모바일 버튼은 최소 48px 이상을 권장한다.

## 22. 로딩, 에러, 빈 상태

### 22.1 Loading

로딩 상태에서는 skeleton 또는 명확한 loading 문구를 제공한다.

예시:

- 추천 공고를 불러오는 중입니다.
- 접근성 정보를 분석하는 중입니다.
- 지도를 불러오는 중입니다.
- 기업 정보를 불러오는 중입니다.

### 22.2 Error

에러 상태에는 다시 시도 버튼을 제공한다.

예시:

- 공고 정보를 불러오지 못했어요.
- 접근성 정보를 불러오지 못했어요.
- 지도 정보를 불러오지 못했어요.
- 네트워크 상태를 확인한 뒤 다시 시도해주세요.

### 22.3 Empty

빈 상태에는 다음 행동을 안내한다.

예시:

- 조건에 맞는 공고를 찾지 못했어요.
- 필터 조건을 조금 넓혀보세요.
- 아직 접근성 정보가 충분하지 않아요.
- 현재 데이터 기준으로 확인 가능한 정보가 없습니다.

## 23. 문구 스타일

### 23.1 기본 톤

문구는 부드럽고 명확하게 작성한다.

권장 톤:

- 친절함
- 단정하지 않음
- 사용자를 위축시키지 않음
- 확인 필요 항목을 구체적으로 안내

### 23.2 피해야 할 표현

다음 표현은 사용하지 않는다.

- 접근할 수 없습니다.
- 출근이 불가능합니다.
- 장애인에게 부적합합니다.
- 지원하지 않는 것이 좋습니다.
- 위험합니다.

### 23.3 권장 표현

다음 표현을 사용한다.

- 확인이 필요합니다.
- 현재 데이터 기준으로는 판단이 제한적입니다.
- 지원 전 확인을 권장합니다.
- 사용자의 선호 조건과 다를 수 있습니다.
- 일부 항목은 추가 확인이 필요합니다.
- 큰 어려움 없이 출근할 수 있어요.
- 일부 구간은 주의가 필요해요.

## 26. 구현 체크리스트

UI를 구현할 때 다음을 확인한다.

- Pretendard가 전역 폰트로 적용되어 있는가?
- 본문 글씨가 너무 작지 않은가?
- 버튼 높이가 최소 44px 이상인가?
- 필터 chip을 누르기 쉬운가?
- 지도 정보가 목록으로도 제공되는가?
- 접근성 점수에 텍스트 설명이 함께 있는가?
- GOOD, CAUTION, RISK가 색상만으로 구분되지 않는가?
- 공고 카드에서 D-Day와 접근성 등급이 잘 보이는가?
- 우측 상세 패널의 탭 구조가 명확한가?
- 하단 지원하기 버튼이 항상 쉽게 보이는가?
- 에러, 로딩, 빈 데이터 상태가 준비되어 있는가?
- 모바일에서 3단 구조가 깨지지 않는가?
- 아이콘 버튼에 aria-label이 있는가?
- focus 스타일이 보이는가?
- 데이터 부족 항목을 “확인 필요”로 표현하는가?

## 27. 최종 스타일 방향

BridgeWork의 프론트엔드는 공공 서비스처럼 신뢰감 있게 보이되, 일반 행정 사이트처럼 딱딱하지 않게 구성한다.

핵심은 다음과 같다.

1. 큰 글씨
2. 넓은 클릭 영역
3. 파란색 중심의 안정적인 UI
4. 지도와 목록의 병행 제공
5. 접근성 점수와 이유의 명확한 표현
6. 데이터 부족 상황을 안전하게 안내하는 문구
7. 좌측 필터, 중앙 지도, 우측 상세 패널의 일관된 구조

기능 3 지역 접근성 지도 화면은 BridgeWork의 대표 화면이므로, 이 스타일 가이드를 기준으로 다른 화면도 동일한 톤과 컴포넌트 체계를 유지한다.
